# 待办协议 v0.9（2026-09-19 定稿，甜心认版）

> 目标：session spoor 能按项目拉出**齐全、条条协商过、排序已确认**的待办清单。
> 三条设计芯：待办贵、待审便宜（不对称门槛）｜ 出账必有收据（机械可查）｜ 优先级是列表属性不是条目属性。

## 一、进门：什么算「协商过」（四件套，缺一不进待办）

一条待办要进「下一步」，四件缺一不可：

1. **归属**：谁的事谁打头（v0.2.8 已有约定）
2. **出处**：协商锚点，三种合法形态——
   - 她直接派的（引她的话+日期）
   - 她应允的提案（引应允句+日期）
   - 已授权范围内的自领（挂授权锚点，如 Orbi「机械层归洄」9/18）
3. **判据**：验收判据（什么状态算办完）
4. **排序态**：在已确认的排序内（见三）

四件套不全 → 不进「下一步」，落**待审**（journal mark 待审·人，条目原文写进journal条目）。
**进待审零门槛，进待办有门槛**——这个不对称保证东西不堵在门外也不在门里烂。
待办 ∪ 待审 = 全部已知工作（「齐全」的诚实定义；机器不发明工作，只保证没进系统的活会被 session 收尾对账提醒捞一遍）。

## 二、格式

### 「下一步」段（STATUS.md）

```
## 下一步
> 排序确认：2026-09-19（甜心）·确认至第3条
- T12 [洄] 修六轨器乐误判 ｜协商9/19「装完music box先复测再修」｜判据：六轨复测全对
- T13 [甜心] Orbi口径三题 ｜派单9/18「材料提前一周拿到」｜判据：口径表入库
- T14 [鸣鸣] 游戏面板 ｜契约6 v0.2·分工表9/1｜判据：面板过契约对照（未排序示例）
```

- **确认线**：`> 排序确认：YYYY-MM-DD（甜心）·确认至第N条`。行序即优先级，前N条=已确认排序；N之后=未排序。没有确认线=整段未排序（合法状态，等她过目）。**新增条目一律追加在段尾**，自然落在确认线下，不会静默继承排序权。重新确认=盖新线（旧线删除，历史在journal）。
- **条目行**：`- T<id> [归属] 标题 ｜出处｜判据：…`
  - id：桌内单调递增，**永不复用**（id是历史锚点，删掉的T12永远属于那条已出账的待办）
  - 分段符用全角竖线｜（ASCII | 也认，但写作用全角，标题/出处内不出现竖线）
- 段内不符合条目格式的行 = lint 报错（要么是旧格式待迁移，要么手滑）

### 出账收据（journal 条目）

办完/退账时，在**同项目**journal 落一条含 id 的收据，两种合法形态：

```
- **[判断]** 2026-09-19 14:00 ✅T12 修六轨误判——判据达成：六轨复测全对（证据：journal/ocean-listen/2026-09-19.md 复测记录）
- **[判断]** 2026-09-19 14:00 ↩T13 Orbi口径三题——退回待审：口径未定，先挂甜心
```

✅=判据达成出账；↩=退回待审出账。收据要素：id + 证据指向（或退回原因）。落完收据**才能**从「下一步」删行。

## 三、优先级 = 列表属性

排序是甜心一次拍一批的动作，不是每条单独谈。所以优先级长在列表上（行序+确认线），不长在条目上。机器面只认：确认线之前=已排序，之后=未排序。

## 四、机器面（三处消费，共用一个解析器）

- **解析器**：`spoor_common.parse_next_steps(text)` → `{confirm, items[{id,owner,head,source,criteria,sorted}], malformed[]}`。server/桥/backstop 三处 import 同一函数，不各写各的。
- **写事件**：`workbench_status` 传 text 写入时落账本事件 `threesome.status.write`：`{project, todos_before:[ids], todos_after:[ids], malformed_after:N}`。只带 id 不带正文（与 journal entry_head 同泄漏哲学）。
- **出账审计**（backstop 新判据）：某桌出现过的 id 全集（账本事件 ∪ 当前盘面）− 当前盘面 − 有收据的 = **出账无收据孤儿** → 报。无窗口限制——「出必有收据」是无时限不变量。
- **桥**：`/api/overview` 每项目加 `todo_items`（id/owner/head/sorted+confirm），`/api/project/{name}` 加全字段条目；原 `todo` 原文段保留（向后兼容，前端渐进切换）。

## 五、迁移与确认流程（2026-09-19）

1. 存量「下一步」逐条迁移：出处从 journal/session 史如实挂；挂不上的 → 待审（不编）。
2. 判据缺失的由洄拟稿，迁移块标注「判据洄拟」——她过目前是临时态。
3. 她在会话里逐桌过：改判据/排序/踢回待审，然后盖确认线（排序确认=她的动作，agent 只代落笔并引会话出处）。

## 六、边界（诚实档）

- 机器查**形状**（四件套齐不齐、出账有没有收据），不查**真伪**——出处真不真归审计（session_search 对勘+她是终审）。
- 「齐全」不被机制保证，被保证的是：待办∪待审=全部已知工作 + session 收尾对账提醒（gap 钩子文案扩展）。
- STATUS 的「下一步」外区域（做到哪/卡在哪）不受本协议约束，保持自由文本。
